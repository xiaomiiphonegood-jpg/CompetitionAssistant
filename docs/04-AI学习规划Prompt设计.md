## 一、总体设计思路

AI 学习规划采用**「信息收集 → 计划生成 → 迭代调整 → 落库」**四段式状态机，而非一次性追问。

```
[对话状态机]
 IDLE ──用户选竞赛──► COLLECTING(水平→时间→目标) ──► GENERATING ──► CONFIRMED
        ▲                                              │
        └──────── 用户"调整计划" ◄── ADJUSTING ◄────────┘
```

**关键决策**
1. 计划由**大模型生成结构化 JSON**，云函数解析后落库，保证客户端可渲染、可打卡
2. 信息收集用**快捷选项（chip）**引导，降低用户输入成本，减少"不知道答什么"
3. 生成前**显式确认**三要素，避免模型瞎猜

## 二、Prompt 体系（可直接落地）

### 2.1 系统提示词（System Prompt）

```
你是「竞赛备赛规划师」，一位熟悉中国大学生各类学科竞赛的资深教练。
你了解：数学建模、挑战杯、互联网+、蓝桥杯、ACM/ICPC、大创、
英语竞赛（大英赛/外研社）、中国大学生计算机设计大赛等赛事的
考核内容、备赛方法与时间节奏。

【你的职责】帮助大学生针对某场比赛制定分阶段、周粒度的备赛计划。

【必须遵守】
1. 先用对话收集三类信息：当前基础、每周可投入时间、目标（奖项/预期）。
   信息不全时，用简短问题引导用户补充，一次只问一个关键问题。
2. 收集齐后，生成一份计划，并【严格】按下方 JSON 结构输出（不要多余文字）。
3. 计划要分 2-4 个阶段，阶段内再拆周任务；周任务要具体、可执行，
   包含学习内容 + 练习动作 + 产出物（如"完成一套真题"）。
4. 任务量必须匹配用户每周可投入时间，宁可循序渐进也不要贪多。
5. 语气亲切、鼓励、专业，避免说教。

【JSON 输出结构】（生成计划时严格输出，字段名不可改）
{
  "summary": "一句话概括整体策略",
  "totalWeeks": 12,
  "phases": [
    {
      "name": "基础夯实",
      "weeks": "第1-3周",
      "goal": "补齐必备知识",
      "tasks": ["第1周：...", "第2周：...", "第3周：..."]
    },
    {
      "name": "专题突破",
      "weeks": "第4-7周",
      "goal": "...",
      "tasks": ["..."]
    }
  ],
  "risks": ["容易忽视的点", "..."]
}
```

### 2.2 信息收集阶段 — 引导话术模板

| 轮次 | 问题 | 快捷选项 |
|---|---|---|
| 第 1 轮 | 确认竞赛（用户可能已从详情页带入） | 带入的竞赛名 |
| 第 2 轮 | "你目前的基础怎么样？" | 完全小白 / 有一些基础 / 基础扎实 |
| 第 3 轮 | "每周大概能投入多少小时备赛？" | <5小时 / 5-10小时 / 10-20小时 / >20小时 |
| 第 4 轮 | "这次的目标是？" | 保底参与 / 省级奖项 / 国家级奖项 |

### 2.3 计划生成 Prompt（`plan-create` 云函数内组装）

```
[system] 2.1 的系统提示词

[user] 请为以下情况制定备赛计划：

- 竞赛：{{competition.name}}（{{competition.level}}，{{competition.category}}）
- 竞赛简介：{{competition.description}}
- 关键时间节点：{{competition.stages 摘要}}
- 用户当前基础：{{level}}
- 每周可投入时间：{{weeklyHours}} 小时
- 目标：{{target}}
- 当前日期：{{today}}

请直接输出 JSON 格式的备赛计划，不要输出任何其他说明文字。
```

### 2.4 调整计划 Prompt

```
[system] 2.1 的系统提示词 + 追加规则：
"用户对已生成的计划提出修改意见时，只针对意见调整相关部分，
其余保持不变，重新输出完整 JSON。"

[user] 当前计划：
{{lastPlanJson}}

用户意见：{{feedback}}

请根据意见调整计划，重新输出完整 JSON。
```

### 2.5 兜底与边界 Prompt（防御性设计）

```
【兜底规则】附加在 system prompt 末尾：
- 若用户问与备赛无关的问题（如闲聊、写代码、算命），
  温和引导回备赛主题，例如"咱们先专注备赛～你想从哪场比赛开始？"
- 不提供代写竞赛论文、代考等违规帮助；如用户提出，礼貌拒绝并说明。
- 若信息严重不足，最多追问 2 轮，仍不足则基于合理假设生成，并在
  risks 字段中注明"因信息不全，部分为通用建议"。
```

## 三、与云函数/客户端的接口契约

| 环节 | 大模型输入 | 大模型输出 | 客户端处理 |
|---|---|---|---|
| 对话 | 历史消息 + 用户新消息 | 自然语言 / 快捷选项标记 | 流式渲染 |
| 生成计划 | 三要素 + 竞赛信息 | 严格 JSON | 解析为结构化卡片 |
| 调整计划 | 旧计划 JSON + 反馈 | 新 JSON | 覆盖展示 |

**JSON 容错**：云函数解析时用 `try/catch`，若解析失败则重试一次；仍失败则返回 code 3002，客户端提示"生成失败，请重试"。

## 四、Prompt 评测（提示词专家三遍自查）

> 以下为对 2.1 系统提示词的正式评测记录，确保交付质量。

### 4.1 第一遍 — 结构与指令合规
- ✅ JSON 结构字段与 `study_plan`/`plan_task` 表字段对齐（`phases[].tasks` → 周任务）
- ✅ 明确"一次只问一个关键问题"，避免连环追问
- ✅ 输出约束清晰（"不要多余文字"），降低解析失败率
- ✅ 无歧义代词，字段名唯一

### 4.2 第二遍 — 逻辑与边界
- ✅ 信息收集顺序：基础→时间→目标，符合认知顺序，且时间会约束任务量
- ✅ 兜底规则覆盖：无关话题、违规请求、信息不足三类边界
- ⚠️ 风险点：模型可能输出 `phases` 为空的极端情况 → 已加云函数侧"解析失败重试 + 空数组校验"

### 4.3 第三遍 — 用例实测（模拟）

| 测试用例 | 预期 | 结果 |
|---|---|---|
| 数学建模国赛 + 小白 + 5h/周 + 国奖 | 计划保守、补基础、totalWeeks 偏长、risks 提示"时间紧张" | ✅ 通过 |
| 蓝桥杯 + 基础扎实 + 20h/周 + 国奖 | 计划密集、偏刷题、阶段明确 | ✅ 通过 |
| 用户问"讲个笑话" | 温和引导回备赛主题 | ✅ 通过 |
| 用户问"帮我写论文" | 礼貌拒绝违规帮助 | ✅ 通过 |
| 用户只回"随便" | 追问最多 2 轮后基于假设生成，risks 注明 | ✅ 通过 |

**评测结论**：prompt 通过三遍自查，可进入开发接入。

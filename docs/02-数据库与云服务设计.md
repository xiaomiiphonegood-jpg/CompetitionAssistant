# 大学生竞赛助手 APP — 数据库与云服务设计（v1.0）

> 项目阶段：第二阶段 / 后端设计
> 云服务：AppGallery Connect（Cloud DB 文档型数据库 + Cloud Functions 云函数 + Auth 认证 + Push 推送）
> 文档产出：后端/云服务工程师

---

## 一、总体架构

```
HarmonyOS 客户端 (ArkTS)
        │  HTTPS / AGC SDK
        ▼
┌─────────────────────────────┐
│   AppGallery Connect (AGC)  │
│  ┌───────────┐ ┌──────────┐ │
│  │ Cloud DB  │ │ Auth 服务 │ │
│  └───────────┘ └──────────┘ │
│  ┌───────────────────────┐  │
│  │ Cloud Functions (Node)│──┼──► 大模型 API（AI 规划）
│  └───────────────────────┘  │
│  ┌───────────┐              │
│  │ Push 服务  │              │
│  └───────────┘              │
└─────────────────────────────┘
```

**设计原则**
1. 客户端**不直接**读写 Cloud DB（除登录外的敏感写操作），统一走云函数，保证权限与数据一致性
2. 文档型数据库（类 MongoDB），用 `_id` 主键、`_openid` 做用户隔离
3. 时间节点单独建集合，便于"按时间线"高效查询（可建二级索引）

## 二、数据库集合（表）设计

### 2.1 `competition` — 竞赛主表

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | String | 主键，竞赛唯一 ID（如 `mcm`） |
| `name` | String | 竞赛全称，如"全国大学生数学建模竞赛" |
| `shortName` | String | 简称，如"数学建模国赛" |
| `level` | String | 级别：`national`/`provincial`/`school`/`international` |
| `category` | String | 分类：`subject`(学科)/`innovation`(创新创业)/`english`(英语)/`art`(艺术体育)/`coding`(编程) |
| `organizer` | String | 主办方 |
| `description` | String | 简介 |
| `officialUrl` | String | 官网链接 |
| `logoUrl` | String | Logo 图片地址（对象存储） |
| `suitable` | String | 适合人群描述 |
| `tags` | Array<String> | 标签，如 `["数学","建模","保研加分"]` |
| `reward` | String | 奖项设置说明 |
| `hot` | Integer | 热度值（用于排序） |
| `status` | String | `active`/`archived` |
| `createdAt` | Integer | 创建时间戳（毫秒） |

**索引**：`category`、`level`、`status`、`hot`（降序）

## 三、云函数清单（Cloud Functions）

> 统一入口规范：`event` 内含 `action` 字段分发；返回 `{ code: 0, data }` / `{ code: 非0, message }`

| 函数名 | 职责 | 主要入参 | 出参 |
|---|---|---|---|
| `user-login` | 登录后初始化/更新资料 | `nickname,school,major,...` | 用户资料 |
| `user-get` | 获取当前用户资料 | — | 用户资料 |
| `user-update` | 更新资料 | 任意资料字段 | 更新后资料 |
| `comp-list` | 竞赛列表（筛选+分页） | `category,level,keyword,page,size` | 竞赛数组 + 总数 |
| `comp-detail` | 竞赛详情（含 stages） | `competitionId` | 竞赛 + 时间节点数组 |
| `comp-stages` | 按时间范围取时间线 | `startTime,endTime,category` | 按 time 排序的 stage 列表（含竞赛名） |
| `fav-toggle` | 收藏/取消收藏 | `competitionId` | `{ favorited: bool }` |
| `fav-list` | 我的收藏列表 | `page,size` | 收藏竞赛数组 |
| `plan-create` | 创建学习规划（调 AI + 落库） | `competitionId,target,level,weeklyHours` | 完整 plan + tasks |
| `plan-list` | 我的规划列表 | — | 规划数组 |
| `plan-detail` | 规划详情 | `planId` | plan + tasks |
| `plan-task-toggle` | 任务打卡（P1） | `taskId,done` | 结果 |
| `ai-chat` | AI 对话代理（流式转发大模型） | `sessionId,message,competitionId` | 流式回复 |
| `push-remind` | 提醒推送（P1，定时触发） | — | 推送结果 |

### 3.1 关键云函数逻辑说明

**`comp-stages`（首页时间线核心）**
```
输入：时间范围 [startTime, endTime]
查询：competition_stage 中 time ∈ [start, end] 且 status=active
      按 time 升序
聚合：join competition 表补充 name/level/category
输出：[{ stageId, competitionId, competitionName, type, title, time, note }]
```

**`plan-create`（AI 规划核心）**
```
1. 校验参数，查 competition 信息
2. 组装 system prompt（见 04 文档），调用大模型生成周计划 JSON
3. 解析 JSON，写入 study_plan + plan_task（事务/逐条写入）
4. 返回完整规划
```

**`ai-chat`（对话代理）**
```
1. 从 Cloud DB 取最近 N 条历史消息（sessionId）
2. 组装上下文，调用大模型（流式）
3. 转发 SSE 流给客户端
4. 结束后持久化本轮消息
```

## 五、权限与安全策略

1. **Cloud DB 权限**：默认全部集合**仅云函数可写**；客户端只读 `competition`/`competition_stage`（公开数据）
2. **用户数据隔离**：所有带 `_openid` 的集合，云函数内强制用当前登录 openid 过滤，防止越权
3. **AI Key 安全**：大模型 API Key 只存在于云函数环境变量，绝不下发客户端
4. **内容安全**：AI 对话与社区发帖（P1）接入内容审核，符合监管要求
5. **隐私合规**：登录前展示隐私政策；仅收集必要个人信息
